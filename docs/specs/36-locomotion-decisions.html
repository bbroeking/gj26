Quick wins — do these, no input needed

Four small changes the research strongly supports. All cheap, all high-confidence. I'd batch them as one short PR.

O1

Swap bindings to industry convention high confidence

Current code: SPACE = Dash, CTRL = Roll. Every shipped ARPG with a dodge puts it on Space — PoE 2, Lost Ark, Hades, post-SOTE Elden Ring all converge on this. Anyone coming from those games will hit Space expecting the defensive verb and get the wrong one.

RecommendSwap to SPACE = Roll, CTRL = Dash. Two-line change in _bind calls.
Cost
2 lines in player_controller.gd:137-138
Source
Bindings research §2 — every surveyed ARPG with a roll uses Space
Risk
Muscle memory for anyone who's been playtesting. Worth it.
O2

Velocity-driven foot-slide fix high confidence

Current: _ap.speed_scale = 0.85 set once at _ready. Foot-slide is present at every speed except the one Meshy calibrated. The fix doesn't need an AnimationTree — just update speed_scale each frame from velocity.length().

RecommendPer-frame: _ap.speed_scale = clamp(velocity.length() / WALK_REF_SPEED, 0.7, 1.3). Calibrate WALK_REF_SPEED by eye in the editor.
Cost
~5 lines added to _physics_process
Source
Locomotion research §4
Visible at
any speed that isn't 1.0× of the reference — sprint and creep most
O3

Add recovery-cancel windows to dash and roll high confidence

Current: zero cancel during Move.DASH and Move.ROLL. Souls, PoE 2, DMC all permit recovery cancels into other locomotion verbs; Hades is the outlier. For a "feels smooth" target, fluid is the convention.

RecommendDefine recovery as last 30% of burst time. During recovery, dash/roll inputs interrupt and start the next burst. Active frames (first 70%) remain committed.
Cost
~15 lines — add an _in_recovery derived flag, check it in match _move
Source
Bindings research §3 + §4 (active vs recovery is the canonical pattern)
Side effect
This is the structural piece O4 (roll i-frame retune) depends on
O4

Reduce roll i-frames from 89% to 60% high confidence

Current: ROLL_IFRAMES = 0.4 of ROLL_TIME = 0.45 = 89% i-frame coverage. PoE 2 is ~50%, Elden Ring light-roll is ~40%, Souls is ~30%. 89% means the roll is essentially fully invulnerable — there's no meaningful recovery window for skilled play to punish.

RecommendROLL_IFRAMES = 0.27 (60% of 0.45s). Lands between PoE 2 and Elden Ring; leaves a real recovery window for O3's cancel grammar.
Cost
1 line
Source
Bindings research §4; verified against Elden Ring + PoE 2 conventions
Confidence
tuning is taste — re-evaluate during playtest pass (step 11)

Deferrals — with reasoning

Three items I'd punt, each for a specific reason. Not "I don't know"; "the right moment isn't now."

O5

AnimationTree migration defer to spec 37

Current code uses plain AnimationPlayer with a crossfade arg. The research-recommended OneShot → StateMachine → BlendTree architecture is the right end-state, but its real payoff is when we add attack animations as overlay clips (spec 37). Doing the migration without attacks-as-overlays means a refactor with no visible improvement.

Defer toSpec 37 (attack pipeline) — the migration becomes load-bearing then. Cost is the same now or later; benefit is visible only then.
Cost when done
~1–2 days. Author data/player_anim_tree.tres, rewrite _play_anim
O6

Locomotion blendspace (velocity-driven walk↔run) tied to O5

Current: discrete Shift toggle between walk_speed and run_speed. Continuous velocity-driven blending requires BlendSpace1D, which requires AnimationTree (O5). Bundled.

Defer withO5. Same blocking dependency.
Note
The discrete toggle isn't broken — it just isn't as smooth as a blendspace would be. Acceptable v1.
O7

Strafe mode when bow is drawn defer to aim system

Ranger archetypes (D3 Demon Hunter, PoE Ranger) typically strafe while aiming — body keeps facing the target, legs sidestep. We don't have an aim/draw system yet; fire is instant via F. Without a "drawing" state to attach strafe to, the decision has no anchor.

Defer toThe spec that adds hold-F-to-draw, release-to-fire aiming (probably spec 37 or 41).

Needs your input — two judgment calls

Where I have a recommendation but the call is yours — either because it's a taste/scope call, or because the research consensus is genuinely split.

O8

Jump — add it at all? needs your input

You named jump as one of the five verbs we'd implement. The codebase deliberately doesn't have one (and SPACE is taken). The shipped-game survey is informative: PoE 2, Diablo 3, Hades, Lost Ark, Last Epoch — none of them have jump. ARPGs default to no jump. The exceptions are Souls-family (Elden Ring) and Sekiro, where jump is woven into traversal and combat.

My takeDefer. The current crypt levels are flat — there's nothing to jump over. Adding jump now buys you a verb without a use case. Reconsider when level design introduces gaps, ledges, or vertical combat.
If yes
~1 day: new binding (Alt? E? Shift+Space?), JumpStart/JumpAir/JumpLand states, coyote+buffer, disable floor_snap_length during ascent
If no
drop jump from the spec's verb list; keep walk/run/roll/dash as the four locomotion verbs
The fork
are we building a Souls-flavor ARPG (jump matters) or a Diablo-flavor ARPG (jump irrelevant)?
O9

Dedicated roll/dash animation clips, or keep the procedural look? needs your input

Current: dash and roll both reuse the "run" clip; roll adds a procedural rotation.x tumble through TAU. The procedural roll is charming — A Short Hike, Tunic, low-poly stylized games often use exactly this kind of "math the model into a flip" approach. The dash reusing run is less charming; it looks like a fast jog.

My takeKeep procedural roll, add dedicated dash clip. The roll tumble reads as intentional style; the dash reusing run reads as placeholder. A Meshy regen for "fast forward lean" or a Blender-authored 0.2s lunge clip closes that gap.
Cost if yes
Meshy regen ≈ 20-30 credits + Blender stitch — half a day
Cost if no
zero — accept current look
Taste lens
do you want our locomotion to read more cozy-stylized (keep procedural everywhere) or more ARPG-crisp (dedicated clips per verb)?
