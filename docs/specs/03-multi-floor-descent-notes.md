# Implementation notes — 03-multi-floor-descent

## Decisions

- **Spec 03 vs foundation Q7 conflict resolved in favor of Q7.** Spec 03's "open decisions" section recommended keeping the gold-exit on non-final floors "per Q3, voluntary return keeps loot." That misread the foundation: Q3 is about death-penalty (soft), Q7 is about voluntary mid-arc exit (forbidden). I followed Q7 — the gold exit disc is suppressed on non-final crypt floors. Only the staircase appears. The chest is also suppressed; only floor `floors` has a reward chest (Hedgemother's room).
- **Spec 03 vs foundation Q5 conflict resolved in favor of Q5.** Spec 03 recommended `tier = ceil(depth / 2)` per-floor scaling. Q5 says tier is CONSTANT across the arc (chart commitment). I kept tier constant — `dungeon.tier` doesn't change between floors. Within a single chart, depth scales narrative pressure (mid-boss, final boss) but not enemy difficulty.
- **Variable floors per chart** (foundation Q5). Charts carry `{ tier, scope: 'crypt', floors }` in the `chart` field. Two starter ledgers shipped: `chart_crypt_short` (tier 2, 4 floors) and `chart_crypt_long` (tier 3, 10 floors). Player sees both `tier` and `floors` in the chart description before opening.
- **Boss-floor formula**: mid-boss on `ceil(floors/2)` = `wolf_alpha` (reskin to "crypt hound" in lore per Q9). Final boss on `floors` = `hedgemother`. For `floors === 4` (pilgrim chart): mid-boss floor 2, final floor 4. For `floors === 10` (deep pilgrim): mid-boss floor 5, final floor 10. Computed in `generateDungeonLayout` from `(depth, floors)`; main.js doesn't second-guess.
- **Per-floor seed**: `floorSeed = Math.imul(baseSeed, 31) + depth` (all `>>> 0` to keep unsigned). Replayable: re-rolling the same arc with the same chart and same RNG sequence gives the same 4 floors. The Q2 "Hades-style finite arc" intent is replayability via *different* `baseSeed` on each chart entry, so we burn a fresh `Math.random()` at `enterDungeon` time.
- **`_descendCryptFloor` flow**: tear down enemies + ground loot + group → bump depth → derive seed → generate next floor → buildDungeonGroup → re-`_populateDungeonEnemies(tier, scope, layout)` → 25% partial heal → log+HUD. Mirrors `swapAuthoredFloor` (existing helper for editor levels) but uses procgen.
- **Floor-clear gate**: `tryTakeStaircase` filters `dungeon.enemies.filter(e => e.alive !== false && (e.hp == null || e.hp > 0))`; non-zero alive → log "Enemies remain" and refuse descent. Mob-table empty for crypt (per spec 02 grill) means floors 1–9 currently spawn nothing, so the gate is a no-op until spec 04 ships niji 6 enemies.
- **HUD**: new `<div id="crypt-depth-hud">` in index.html, positioned absolute under the title at the top of the canvas, styled with a purple glow to match the staircase color. Hidden via `display: none` unless `dungeon.active && arcScope === 'crypt'`. Updated by `_updateCryptDepthHud()` from `enterDungeon` / `_descendCryptFloor` / `exitDungeon`.
- **Death + exit reset**: existing `handleDeath` already routes through `exitDungeon`, which now also clears `dungeon.arcScope / depth / floors / baseSeed`. Same path runs on natural arc completion (final-boss chest looted → gold exit clicked → exitDungeon). Re-entry needs a fresh chart (D1 — chart consumed on entry already).
- **No voluntary mid-arc exit** (foundation Q7). Implemented by suppressing the gold exit disc on non-final floors. The exit COORDINATE still exists in the layout (used by the staircase for orientation), but the player has no way to step on it to trigger `exitDungeon` because there's no rendered affordance and `interactAt` checks `dungeon.layout.exit.x === tx` after a click on the tile. We could harden by also checking `layout.cryptFinalFloor === false` to block the click, but in practice the missing disc removes the path.

## Tradeoffs

- **Spawn-block extraction**. Pulled the procgen-spawn loop, `dungeonSpawnFns`, and `AUTHORED_SPAWNS` out of `enterDungeon` to module level so `_descendCryptFloor` can re-use them via `_populateDungeonEnemies(layout, tier, scope)`. Also extracted `applyAffixesToEnemy`. Total enterDungeon-internal helpers moved out: 3 (~70 lines). Cleaner than duplicating the spawn block; downside is a few more module-level functions to scan in main.js.
- **Browser module caching**. Spent ~10 min debugging "why isn't enterDungeon picking up my edits" — turned out the browser cached the ES module aggressively, even past `location.reload(true)`. Cache-busted via `?v=20260520-spec03` on the main.js `<script>` tag + `Cmd+Shift+R`. Documented for the next round.
- **Dev exposures** (`window.__dungeon`, `window.__descendCryptFloor`). Added two debug hooks for smoke-testing. Left in; they're cheap and useful for future arc work. Easy to gate on a dev flag later if needed.

## Surprises

- **Pre-existing `tryTakeStaircase`** already routes via `localStorage` for authored multi-floor levels. Added a `sc.crypt && dungeon.arcScope === 'crypt'` early-return branch ahead of the localStorage path so the same player-step handler dispatches to procgen vs. authored without an upstream change.
- **`generateDungeonLayout` was called with extra params** by my changes — the old signature was `(seed, affixes, scope)`. The new `(seed, affixes, scope, depth=1, floors=1)` is backwards-compatible (defaults preserve single-floor behavior). All existing callers — `enterBiome`, dev console, openChartFromInventory — keep working without modification.

## Followups

1. **Chart UI shows floor count.** The `chart_crypt_short` / `chart_crypt_long` descriptions already mention floor counts in prose, but the chart's tooltip in the inventory should explicitly read `Tier 2 · 4 floors` so the commitment is visible at a glance. Easy ITEMS-level change.
2. **Cook quest gives the first Crypt Ledger** (foundation D5 — quest NPC for the first ledger = Cook). Currently the player has to spawn one via dev console. Add a one-shot quest node on Cook's dialog tree that hands over `chart_crypt_short`.
3. **Crypt Ledger recipe at chartmaker** (foundation D4 — recipe unlocks after intro quest). When the player completes the Cook intro and the first arc, the chartmaker's recipe list adds Crypt Ledger entries so the player can mint more.
4. **Floor-clear gate is no-op until spec 04**. Currently mob tables for crypt are empty (spec 02 grill outcome), so descent is unrestricted. Once spec 04 ships niji 6 enemies, the existing gate fires automatically.
5. **Stairs GLB still unused for the descent disc.** Spec 02 followup #5 noted `dungeon_crypt_stairs_v1.glb` is preloaded but not rendered. Spec 03 emits a purple disc (same as the authored-floor staircase) at `sc.x, sc.y`. A polish pass could swap the disc for the GLB when `scope === 'crypt'` — visible 3D staircase rather than a glowing puck. Self-contained change in `buildDungeonGroup`'s staircase loop.
6. **Mid-arc death loses everything**. Per Q3, death-during-arc returns the player to town with full HP + inventory intact but burns the in-progress arc. Re-entry needs a new chart. Worth a UI confirmation modal on death-during-arc so the player understands the cost, OR a "you keep what you found" log line that surfaces what they did claim.
7. **Per-floor affixes rolling cadence** (spec 03 Open decision). The spec recommends rolling 1 affix on floors 1/3/6/8, none on 2/4/5/7/9/10. Not implemented in v1 — affixes are still chart-level, applied once at entry. Worth picking up when affix variety expands.
8. **Visual differentiation between mid-boss and final-boss floors**. Currently both load with crypt assets. A slight palette/lighting shift on the Hedgemother floor (more violet ambient, more fog?) would make the final-floor arrival feel different. Spec 05 may cover this.
