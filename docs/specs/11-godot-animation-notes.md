# Implementation notes — 11-godot-animation

## Decisions
- **Meshy MCP gate passed** on the second run (the user set `MESHY_API_KEY` + restarted). Balance at start: 1740 credits.
- **The original cleaned GLBs cannot be Meshy-rigged.** All 5 `meshy_rig` calls failed with "Pose estimation failed" — Meshy's auto-rig pose estimator (Mechoux) can't read the chunky low-poly stylized meshes `clean_ai_mesh.py` produces. They were authored for *procedural rotation* animation (named groups Body/Head/Arm_L…), never as skeletal-riggable humanoids. No credits charged — it fails pre-charge.
- **Pivot: regenerate the cast in Meshy with `pose_mode="t-pose"`, then rig those.** Chosen by the user over the procedural-GDScript fallback and over skipping animation. Accepted tradeoff: the new models are fresh designs that won't pixel-match the existing crypt art / the three.js game.
- **Meshy 6** for all generations (user choice — 20 credits/model, matches spec 04's quality). Budget ≈ 140 credits.
- **4 enemies via `image_to_3d`** from the existing concept PNGs in `docs/concept-art/enemies/` — keeps the regenerated models close to the intended designs.
- **Hedgemother via `text_to_3d`** — no boss concept art exists. Prompt built from `BOSS_SPEC.md` (bramble-queen, thorn crown, moss-vine robe, pale bone face, gold eyes).
- **4 enemy GLBs committed + pushed** to `origin/main` (commit `570be32`) so Meshy could fetch them by `raw.githubusercontent.com` URL — though that path is now moot since we regenerate rather than rig the existing ones. The commit stands (those GLBs belonged in the repo regardless).

## Deviations
- **Spec step B assumed rigging the *existing* GLBs.** Reality: those GLBs are un-riggable by Meshy (see Decisions). The spec's intent — "the cast animates via Meshy" — is met by regenerating + rigging instead. The static `_v1` GLBs stay untouched; the new animated models land as `_rigged.glb`.

## Tradeoffs
- **Idle-only `_rigged.glb` files.** Rigging includes free walk + run, but those clips live on the rig task; the downloaded `Animation_Idle_withSkin.glb` carries only idle. Since the Godot player is still a capsule (no player GLB), nothing consumes a walk clip yet — idle-only is exactly the visible need. `anim_driver.gd` has the walk/idle switch wired but dormant.
- **50K-poly remesh target.** Low enough to clear the 300K rig cap with margin, high enough that pose estimation still had geometry to read. The resulting `_rigged.glb` files are 6–15 MB each (Meshy 6 mesh + skin + texture) — heavy vs the ~5K-tri `_v1` GLBs, acceptable for an eval.

## Surprises
- **Meshy auto-rig is built for Meshy-native humanoids.** It expects a model generated by Meshy's own text/image-to-3d in t/a-pose. An externally-authored low-poly mesh — even a clearly humanoid one like the skeleton — fails pose estimation. The rig tool's docs hint at this ("source model should be generated with pose_mode='t-pose'"); it reads as a quality suggestion but is a hard prerequisite.
- **Meshy 6 generation cost ≈ 29 credits/model, not ~20.** The 5 generations cost 145 credits total — the whole "~140" estimate, before any rig/animate. Final spend landed ~205 (the user re-approved mid-run).
- **Meshy 6 meshes are enormous** — 317K to 1.4M faces. 4 of 5 exceeded the 300K rig cap and needed a `meshy_remesh` pass that the spec hadn't budgeted (+20 credits).
- **The rat (quadruped) cannot be rigged.** Meshy's pose estimator is humanoid-only. Expected per the spec's open decision — the rat falls back to its static `_v1` GLB via `layout_loader._resolve_model`.
- **Ghost rigged fine.** The spec flagged the legless ghost as a risk; Meshy's t-pose regeneration gave it enough of a humanoid upper body to pose-estimate. Only the rat failed.

## Followups
- **Rat animation.** The quadruped never rigged. Options: a GDScript procedural bob/scuttle in Godot, or a non-Meshy quadruped rig. For now it's static.
- **Walk clips unused.** The rig's free walk/run aren't downloaded. When a player GLB exists (or enemies get AI movement), download the rig-task GLB too and `anim_driver.update()` switches to walk.
- **`_rigged.glb` files not committed.** They're 6–15 MB each (~40 MB total). Left uncommitted — committing 40 MB of binary to git is a real weight; the user should decide whether they belong in the repo or in asset storage.
- **Visual confirmation.** The scene boots clean, the probe confirms each rigged GLB has an `AnimationPlayer` + idle clip, and `play_idle` runs without error — but I could not screenshot the animation in motion to 100% confirm the idle plays. Worth a 10-second look in the running window.
- **Regenerated models drift from the crypt art.** The new Meshy-6 characters are fresh designs, not the spec-04 concept art's exact look. Accepted tradeoff (the user chose the regen path knowing this).
