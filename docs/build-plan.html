Build Plan

Movement first, then slice 1, then the differentiator. Design-spine layers fill in along the way.

How to use this board

Each item carries a status: in progress todo in progress done deferred gate. Gates are stop-and-playtest checkpoints — we don't ship past them without sign-off.

The reframe driving the order: with the cozy-skilling spine (ADR 0003), the player spends ~80% of their time walking the world / gathering, ~15% in the channel-gather, ~5% in combat. So movement is priority #1 not for combat-feel but because walking through Bramblewood is what the player feels for most of the session.

Batch A — Quick Wins from spec 36

~30 lines · 1 PR · ~half day

Zero design decisions left. Already resolved in 36-locomotion-decisions. The fastest possible "the world feels better" win.

  • Swap bindings to industry standard — SPACE = Roll, CTRL = Dash (current code has them inverted). Every shipped ARPG with a dodge puts it on Space.
    in progressplayer_controller.gd:137-138
  • Velocity-driven foot-slide fix — replace static speed_scale = 0.85 with per-frame clamp(velocity.length() / WALK_REF_SPEED, 0.7, 1.3). Foot-slide is visible at every speed except the calibrated one.
    in progress~5 lines, _physics_process
  • Recovery-cancel windows on dash & roll — last 30% of each burst becomes cancellable into the other locomotion verbs. Current code is zero-cancel; Souls/PoE/DMC all permit recovery cancels.
    in progressmatch _move state, +_in_recovery
  • Drop roll i-frames 89% → 60% — change ROLL_IFRAMES = 0.4 → 0.27. 89% means the roll is effectively fully invuln — no recovery to punish. 60% sits between PoE 2 and Elden Ring.
    in progress1 const change
acceptanceRoll on Space, walk→sprint shows no foot-slide, dash mid-roll-recovery works, roll has a punishable tail. One PR, ~30 lines.

Batch B — Traversal feel pass (the new emphasis the spine demands)

~1 day build + 1 day tuning

Spec 36 weighted combat movement; the cozy-skilling spine flips that. Most of the session is walking around looking for things to gather. Make that texture good.

  • Split ACCEL / DECEL / TURN_DECEL and tune for traversal feel. Current code has a single ACCEL=12 doing both speed-up and stop. Recommended start: 20 / 18 / 30.
    in progressplayer_controller.gd consts
  • Camera follow polish at walking pace — damping + slight lead on direction change so the camera feels alive, not glued. Closes the open spec-09 followup.
    in progresscamera_rig.gd
  • Slow-walk mode (Shift held) — meditative stroll. Cozy games live or die on whether just walking feels good. Current code uses Shift = walk modifier; this elevates it to "intentional cozy pace" with its own anim time-scale.
    donealready via Shift + foot-slide fix
  • Footstep audio hooks — placeholder beats per surface tile. Wires into the missing Audio design layer; defer real samples but stub the hook.
    deferred→ Audio layer (L10)
acceptance20-minute playtest: walking from town to a forage spot to the hearth and back feels good on its own, before any gather mechanic is added. The recorded playback doesn't make you flinch.

Batch C — Channel-gather mechanic

slice-1 work; also the gather-feel half of movement

The hold-to-channel from spec 37 is technically a gathering mechanic, but it is movement during gathering — the channel sets the pace, the cancel-on-movement decides whether you commit. Belongs in the movement arc.

  • Hold-to-channel interaction — press, progress bar fills over channelTime, completes → drop + XP burst. New: src/game/gathering.js in three.js is the design prototype; reimplement in GDScript as scripts/gathering.gd.
    todonew gathering.gd
  • Cancel on movement — walking away mid-channel cancels with no reward. Reads as "I'm committing to this; if I move, I bail."
    todoin gathering.gd
  • XP-burst beat + luck-pop visual — floating text, sound stub, "+1!" surprise from the spec-37 luck system. The dopamine moment under the meditation.
    todoreuse hit-feedback patterns

Slice 1 — gather → cook → sustain → fight

the spine's first proof

The first complete loop, end-to-end

smallest version that proves the spine

Per ADR 0003 — we build one fun loop, end-to-end, before widening. Godot already has the hearth, combat, inventory, equipment, and HP/heal flow; the only net-new is the channel-gather and the wiring.

  • Add channel-gather to one forageable + one fishing spot — the smallest content footprint that proves the mechanic. Pick something simple from the existing items: whitleberry + sardine.
    todoMovement Batch C
  • Wire gathered item into existing hearth cook flow — make the cooked output of whitleberry/sardine reach the inventory.
    todohearth.gd already exists
  • Confirm cooked food heals — exercise the existing consume → HP path.
    todoalready wired in player_controller.gd
  • Short encounter that consumes the food — a single skeleton or rat (Godot has both), positioned so the player needs to heal between fights.
    todoexisting combatant + enemy assets
  • Award Wilds XP + Cook XP on the right beats — gather awards Wilds, hearth-cook awards Cook.
    todoport from src/game/skills.js
playtest gateIs it fun? Record a 20-min session walking → gathering → cooking → fighting. Watch it back. The cozy-skilling spine is only validated when this loop earns repeat sessions without outside motivation. If it doesn't, the spine itself goes back on the table (per ADR 0003's revisit triggers).

Slice 2 — Cartography meta-loop

the differentiator · gated

The chart-makes-a-dungeon meta-loop

~49 files of three.js design to port

Cartography is the genuinely novel system — and the meta-loop that ties skilling to discovery. But it's also the biggest port. Lead with the smallest fun loop, layer the unique hook on a working base.

  • Cartography rebuild in Godot — port the 8 cartography design docs + inscribing table + keystones. Reimplement in GDScript. The three.js code is the design prototype; the docs are the source of truth.
    deferred→ until slice 1 passes
  • Chart → dungeon link — an inscribed chart spawns/unlocks a dungeon at a higher tier than the player's current reach.
    deferred
gateSlice 2 doesn't start until Slice 1 passes the "is it fun?" playtest. If the cozy spine doesn't hold up there, cartography won't save it.
