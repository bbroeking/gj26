# Deep Systems — Red-Team Findings

> Adversarial review across all 15 [[Systems Interlock Map|deep system designs]]. Verdict below is **CONDITIONAL**: the designs cohere and respect the ADRs, but contradict the *shipped code* on itemization (a live weapon/gear ladder the designs claim doesn't exist). These are the required reconciliations before building.

## Verdict

CONDITIONAL — the designs are coherent with each other and largely faithful to ADR 0003/0005/0006, but they are NOT faithful to the SHIPPED CODE on the one axis they all lean on hardest: itemization. A full ARPG gear-and-weapon ladder (shortbow→longbow→warbow tiers, normal/magic/rare rolled prefix/suffix stat affixes via data/affixes.gd, scaling combat through player_controller._derive_stats) is live, tested, and asserted by the economy gate (gear>=12). Nearly every design asserts 'one verb, no new weapon class or gear tier ever, itemization is only the trophy ritual' as if that ladder doesn't exist. Until a design explicitly reconciles or retires the shipped weapon/gear ladder, the demo's central differentiator claim is contradicted by its own running build. Fix that interlock, ground three formula-cites in the real signatures, and the package is buildable.

## Top fixes (ordered)

- RECONCILE THE SHIPPED GEAR/WEAPON LADDER FIRST. Before any combat/skills/items design ships, decide and document: does the demo (a) remove starsilver/warbow/longbow weapon tiers and the rolled prefix/suffix gear affixes (data/affixes.gd, crafting.gd weapon recipes), or (b) freeze them at zero combat power (strip fire_rate/crit from _derive_stats gear sums)? Every 'one verb, no gear tier ever' claim is false against the running build until this is resolved. This is the linchpin — the trophy-ritual Ledger and dissolve-to-dust sink only make sense after it.
- FIX THE CO-OP DETERMINISM BREAK: route layout_loader.gd:813's bare randf() trophy roll through the chart-seeded _rng, and add a co-op build-parity guard/test, before any co-op, trophy-chain, or Atlas-credit work. It is a live divergence bug, not a future risk.
- CUT MULTIPLAYER CO-OP TO TRUE CORRECTNESS: ship only the _boss_state telegraph/Poise RPC + ONE revive path. Defer reconnect-grace + sleeping-puppet + Party Lantern UI + voiced join/leave lines to Horizon. Rename 'Second Pour' revive to avoid the shipped wilds perk collision.
- UNIFY THE SAVE MIGRATION LADDER ACROSS ONBOARDING + PROGRESSION + CHART LOOP: one VERSION bump, one MIGRATORS array, one set of reserved keys, additive-only defaults. Land the back-up-real-SAVE_PATH fix for _test_save_roundtrip BEFORE the ladder so Phase-0 testing can't nuke a dev save. Keep the affix_good/affix_bad boolean path intact when adding the typed twin table (additive only).
- GATE THE TWO POWER-SPIKE MECHANICS ON BALANCE-SIM BEFORE SHIP, NOT AFTER: (a) Wayfinder's Mark full-cooldown-reset-per-Reel against 30-60s bosses, and (b) compounding Deepening×Festival×tier density vs the enemy-count cap. Add a deterministic headless Poise-fill stub so test_skills can actually assert the one new reading mechanic.
- GROUND THE FORMULA CITES IN REAL SIGNATURES: Game.craft is an instance method not static; ink_stability_bonus reads ink.bias._stability not a per-instance field (specify the refined_ink migration); boss.gd has no in_recovery_window/poise yet (author the vulnerable-window predicate against real _charging/_atk_cd/_telegraph vars); summit template uses kind 'hedgemother_queen' not the scaled 'hedgemother_v2' the capstone design assumes — reconcile so the capstone isn't a new boss.
- RESOLVE THE PALECHALK SEMANTIC COLLISION: 'palechalk' is already a raw ore feeding GEAR smithing. Decide whether the new Palechalk Ink uses a distinct deep-ore material (e.g. pale_deepore as the Gathering design names) and whether the existing palechalk gear recipes stay, so the 'gather-only, ink-refine is the sole sink' claim is actually true in data.

## Cozy-spine drift

- ITEMS/GEAR/ECONOMY + COMBAT + SKILLS all claim 'fire_rate scales the Bow ONLY; gear never adds power; no new weapon class or gear tier ever; itemization is the trophy ritual.' The shipped code disproves this: data/crafting.gd ships longbow_smith / palechalk_longbow_smith (magic) / starsilver_longbow_smith (rare) and items.gd defines shortbow/longbow/warbow as category:weapon. data/affixes.gd rolls Sharp/Heavy/of Fury/of Swiftness onto gear, and player_controller._derive_stats (line ~1022) folds sums.fire_rate from equipped weapons into fire_cooldown. So today a rolled rare longbow literally out-fires the base bow — the exact gear treadmill the Ledger design says it replaces. This is the deepest cozy-spine drift in the set and no design acknowledges it.
- CRAFTING/INKS: the design frames 'Palechalk Ink' as a NEW deep-ore→ink refine step and asserts deep ore is 'gather-only by construction, its only sink is the ink-refine step.' But `palechalk` already ships as a raw gatherable (gather.gd:175, req_lv 7) whose only sinks are GEAR smithing recipes (palechalk_ring/longbow/jerkin). The proposed cozy ink-refine chain is being layered onto a material that currently feeds the weapon treadmill — without that being named, the 'cross-trade chain made tangible' actually deepens the gear ladder it claims to avoid.
- ITEMS/GEAR/ECONOMY: 'dissolve-gear-to-ink-dust' presupposes a gear loot stream worth dissolving. In a true one-verb game there is no gear to melt. The sink only makes sense BECAUSE the ARPG gear ladder exists — so the design quietly relies on the very system the doctrine forbids, rather than removing it. Cozy-washing an ARPG drop sink is still an ARPG drop sink.
- TRADES/COMBAT: Huntcraft XP = max(2, hp_max/3) per kill 'fed by ALL kills everywhere' plus elite retinues, Tyrannical/Festival-Pace density dials, and pack-size scaling means the fastest XP faucet in the game is killing, not gathering/cooking. ADR 0003 says skilling is the spine and combat is one verb; the leveling design makes combat a first-class, always-on XP engine across all four regions. Worth an explicit guardrail that combat XP throughput cannot dominate the gather/craft faucets.

## Scope violations

- MULTIPLAYER CO-OP: scope says 'finish Phase C correctness and STOP,' but the demo bundle still adds Downed-not-dead state + 20s bleed + 3s revive channel + Wildcraft 'Second Pour' revive flavor + 30s reconnect grace with sleeping-puppet bodies + away_since TTL + Party-UI Lantern (roster/invite-by-IP/kick) + Bramblewood join/leave/downed/revive voiced lines through the lore-grader. That is a co-op FEATURE pass, not just the load-bearing boss-state RPC correctness fix. For a tiny team this is the most over-scoped single design; recommend cutting to (a) boss/telegraph/Poise RPC and (b) one revive path, deferring reconnect-grace + Lantern polish.
- PROGRESSION + CHART LOOP: 'Living Atlas v1 — completing 3 Pale Veins charts restores one walkable town corner, well animates, Hod arrives' plus a 'minimal 1-2 page Almanac' each restoring a corner is two town-growth systems in the demo. The Chart Loop's own open question flags the double-feel risk. Town-state animation + NPC arrival choreography is art/scene work a tiny AI-pipeline team will under-estimate; recommend ONE corner restore via ONE counter for the demo.
- CHARTS/AFFIXES: the Pale Veins per-biome flavor table (~6-8 affixes + Boar den) plus a typed good/bad behavior table for ALL ~16 affixes plus biome-as-second-axis plus rumor headers plus Smudge Stick plus first-time-affix teaching is a large interlocking workstream presented as demo. Several of these (full typed-table migration of all 16, biome flavor strings for the whole roster) are really the seam for the Horizon multi-biome Balatro table; only the Pale Veins subset is demo-necessary.
- SAVE: the migration ladder + non-destructive roundtrip test + 256KB budget assert + reserved Horizon keys (charter/almanac/codex/deepening) is correct and necessary — but note CLAUDE.md's own warning that _test_save_roundtrip writes-then-deletes the REAL save path. The design's 'back up/restore real SAVE_PATH' must land BEFORE the ladder work or the Phase-0 test itself risks nuking a dev save; sequence it first.

## Anti-escalation breaks

- ITEMS/GEAR: Ledger LEDGER_CAP=3 with one boon per shipped boss is fine and horizontal — BUT the shipped warbow/longbow/starsilver rarity ladder IS a gear-tier escalation that already exists in the build. The anti-escalation doctrine (P6/P8) is stated as 'never a new gear tier,' yet the demo would ship ON TOP of an existing multi-tier gear ladder. Either the doctrine must be amended to 'freeze and de-power the existing ladder' or a design must own removing starsilver/warbow. As written, the designs claim a cut-line the code already crossed.
- SUMMIT capstone (Enemies/Bosses): 'Summit = same hedgemother_v2 scaled 3.75→4.6, quieted not killed' is correctly anti-escalation — good. But charts.gd ships template 'summit' with boss_kind 'hedgemother_queen' (a DISTINCT kind string, not hedgemother_v2). The design says reuse the scaled hedgemother; the data says a separate queen kind. Reconcile, or the capstone quietly becomes a new boss.
- COMBAT/SKILLS interlock: Wayfinder's Mark finisher RESETS ALL skill cooldowns + refunds Focus on every boss Reel. The designs' own open questions admit this 'may over-trivialize' and 'may trivialize if a player dumps three cooldowns.' A full-cooldown-reset-per-Reel against a 30-60s TTK boss is a power spike that can collapse the read-and-respond fantasy into a burst-dump — it risks escalating the one verb into a combo system. Needs the promised balance-sim gate BEFORE it ships, not after.

## Buildability gaps

- CRAFTING design cites 'one mutation point Game.craft(station_id, recipe_id)' as a STATIC mutation point; in code it is an INSTANCE method on the Game autoload (game.gd:351 `func craft(...)`, called as game.craft). Minor, but the ink_stability_bonus extension, the per-instance stability_bonus field, and the 'replace the constant _stability for refined inks only' edit all touch charts.gd's ink_stability_bonus (which currently reads ink.bias._stability, NOT a per-instance field) — the design must specify the migration for already-discovered refined_ink instances or old saves will read a missing field.
- NEW ledger.gd / data/ledger.gd::TROPHY_BOONS and _test_ledger_boon_horizontal / _migrate ladder / MIGRATORS array / _boss_state RPC / Poise-on-boss.gd / ui_config.gd / biome_affixes.gd / strings.gd are ALL net-new files asserted as demo. None exist yet (confirmed: no ledger.gd, no net_game _boss_state, no Poise in boss.gd). That's fine as a plan, but several designs cite these as if shipped ('reusing the existing inscription verb,' 'rides the existing boss.gd phase machine') — boss.gd has _charging/_atk_cd/reset_fight but NO in_recovery_window / _in_window / poise fields. The vulnerable-window predicate the Combat design specifies must be authored from scratch against the real boss phase vars.
- FOUR-SUITE GATE mismatch: every design invokes 'the four-suite gate' but the repo has ~17 test_*.gd files; CLAUDE.md names exactly four as load-bearing (test_wyrd_loop, test_wyrd_dungeon_scene, test_wyrd_transitions, test_skills). New mechanics (Poise, vein-reading, ink-refine, ledger, migration ladder, co-op _boss_state) need explicit assertions added to those four — but several designs only say 'add to economy-gate test' or 'balance-sim sets it,' with no concrete suite hook. Vein-reading's GRAIN_WINDOW auto-grant under WYRD_FAST_CHANNEL is the one design that correctly names its determinism hook; the others should copy that pattern.
- Vein-reading + branching-seam + Poise are real-time/timing mechanics; the headless suites are deterministic. The designs lean on WYRD_FAST_CHANNEL for gather but give no equivalent deterministic harness for Poise fill (depends on _in_window timing) or for the Reel skill-reset path — so test_skills (the suite that catches a dead keypress) cannot currently assert the new reading mechanic. Specify a headless Poise-fill stub before relying on the four-suite gate to protect it.
- ONBOARDING/SAVE: replacing the destructive version-mismatch discard (save_game.gd line ~63, confirmed) with an ordered ladder is correct, but seen_affixes/seen_debriefs/strings_locale + region_depth/atlas_counts/codex_seen are added by MULTIPLE designs (Onboarding, Progression, Chart Loop) each assuming its own migrator slot. They must share ONE migration ladder and ONE VERSION bump or they will fight over the m1_to_2 index — coordinate the schema bump across all three before any ships.

## Interlock conflicts

- CO-OP DETERMINISM vs DUNGEON GEN (live bug, confirmed): layout_loader.gd:813 uses a BARE `randf() < 0.25 * _trophy_mult` for the elite trophy roll inside the per-peer build path, while everything else routes through the chart-seeded `_rng`. Co-op peers will diverge on which elites carry trophies. The Dungeon Gen design flags this as an open question; it is actually a shipped determinism break. Co-op + trophy chain + branching-seam reveals all sit on this seam — must route through _rng before any co-op trophy/atlas-credit work, or party loot/Atlas counters desync.
- CO-OP NAME COLLISION (confirmed real): the 'Second Pour' downed-revive flavor collides with the SHIPPED Wildcraft Lv17 crafting perk 'second_pour' (game.gd:446, perk_active('wilds','second_pour') gates a +1 craft yield). The Co-op design's own open question catches this; it must be renamed before any strings ship or perk_active lookups and the revive flavor will entangle.
- AFFIXES typed-table migration vs RUNTIME: the Affixes design wants to promote the `__bad` string suffix to a typed good/bad table 'so the dungeon reads the resolved effect.' But the runtime does NOT read resolvedId/__bad for modifiers — layout_loader._read_chart_modifiers and game.affix_good/affix_bad branch on id + the `good` BOOLEAN (confirmed game.gd:766-776). So the typed table is lower-risk than claimed for modifiers, but the design must NOT break the boolean path that 30+ call-sites depend on; the migration is additive-only or it breaks every affix consumer at once.
- PROGRESSION Deepening (Horizon) vs DUNGEON GEN density: affix_slots = template.affix_slots + region_depth and enemy_density *= 1+0.12*depth thread through run_cfg — but dungeon_gen's generate-and-test already flexes bands per-chart via _score_cfg, and layout_loader stacks _density_mult *= cfg.enemy_density *= tier HP mult. Depth density compounding on top of Festival Pace (1.5x) on top of tier scaling can blow past the per-pillar enemy-count perf budget the Progression open question worries about. The interlock needs one authoritative density-cap clamp, not three multiplying sites.
- SUMMARY CARD honesty vs ROLL TIMING: Chart Loop, Affixes, and UI all promise 'HONEST live odds straight from compute_weights/effective_stability, tested for no drift.' But inscribe() in charts.gd resolves the twin coin AT inscription (rng inside inscribe), so by the time a card could show 'live odds' for an already-stamped chart the twins are already resolved. The card can show odds only at the pre-stamp preview; the Smudge Stick then re-rolls a RESOLVED twin. The three designs must agree on whether the card shows pre-roll probabilities or post-roll resolved state — currently they describe both ('honest live odds' AND 'resolved/likely twins in plain English') which the single inscribe() call cannot serve simultaneously.
